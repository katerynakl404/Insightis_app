# Shared workspaces — locked rules

Source brief: Claude Doc «Дизайн: Shared workspaces, фаза 1» (Victor, 2026-09-25; epic AIINS-1852;
design tasks AIINS-1858 / 1866 / 1873 / 1892 / 1887, history 04 / AIINS-1882). Patterns borrowed from
the AI connectivity workspaces prototype where they fit (its list, the opened workspace, its picker dialogs).
Approved 2026-10-22.

| # | Rule |
|---|---|
| 1 | **Existing elements first.** Every piece is DevartUI or an existing kit component; what is new lives in the kit once: Workspaces (store, WsNotice, WsSharedBy, WsOwnerMark, WsNames, wsToast, useWsPanelActions …), WsList, WsOverview, WsMembers, WsConnections, WsMetrics, WsFiles, WsDialogs, WsEmail, LoadMore, StatusMark, and the details panels ConnectionDetails / MetricDetails / FileDetails on DetailsPanel. DevartUI's own wherever it has one: SearchInput, FilterMenu, AlertStack, ConfirmationDialog (ported in `ds-bridge/` until the bundle ships them), ChoiceCard, StatusView, ListSelectionBar (user, 2026-10-22: "треба по максимуму з деварт юа"). |
| 2 | **On by default.** The feature is on on every approved page (user, 2026-10-19: the Off/On switch was noise); `?ws=0` turns it off, and the page then renders as approved. The Workspaces pages (`approved/workspaces.html`, `approved/workspace-emails.html`) are the feature itself. |
| 3 | **One person, one world.** They own some workspaces and were invited to others; the role is each workspace's. Review switches are live and independent (no reload, nothing made on the way is lost), only where they act: the list — Plan (Paid · Trial · Free) · Invited (Active · Blocked) · Data (Filled · Many · Empty · No workspaces) · Reset Data · Theme; a workspace — Plan · Role (Owner · Member: which workspace opens) · Invited (not on one's own) · Data · Reset Data · Theme; Data Sources, Files, Metrics, Account — their own + Plan · Invited · Reset Data; Chat — + Owner; emails — Email · Reset Data · Theme. |
| 4 | **Workspaces in the sidebar** — a nav row under New Chat → `approved/workspaces.html`. The list and an opened workspace are one page (`?w=`), as in AI connectivity. |
| 5 | **The list**: title action Create Workspace (round; locked → Pro on Free); search (DevartUI SearchInput); an Owner filter (FilterMenu: Anyone · Me · Shared with me — only when there are both); the count line in one 44px slot (MetaRow 44px and ListSelectionBar 37px differ); every row can be picked — one's own to delete, an invited one to leave (user, 2026-10-19: "але ти можеш покинути"); bulk Leave / Delete are disabled with the reason when the pick mixes both (user, 2026-10-20); 20 + Load more; no workspace → the first-run Banner, no match → "No matches found". Columns: Name (+ the Blocked mark) · Owner · Members · Connections (its menu opens Connection details in place) · Last activity · ⋮ — no Files column (user, 2026-10-20). Invite Members / Add Connection from the ⋮ open the dialog in place; Invite then goes to the Members tab, Add Connection stays and its toast links there. |
| 6 | **An opened workspace**: Overview · Connections · Metrics · Files · Members, for the Owner and an invited Member alike (a Member's Members tab is read-only). Below 640px the tab strip scrolls sideways (no scrollbar). The Owner's tabs act as the own pages do — Data Sources' cells and ⋮, Metrics' rows (switch, Edit · Duplicate · Delete), Files' ⋮ and bulk bar — plus **Remove from Workspace**, which always asks first (user, 2026-10-22: "⋮ і клітинки як на власних сторінках, Remove from Workspace лишається додатковою дією"). The title action follows the tab: Add Connection · Create Metric (in place; the metric goes with its connection) · Add Files · Invite Members. Read-only for a Member: every management control is absent, not disabled. |
| 7 | **Overview**: the General card (name, Edit — name and description — for the Owner, description, who made / shared it), then three tiles Connections · Files · Members; the Owner's carry "+" (add one in place) always, no gear (user, 2026-10-21: "завжди + не треба налаштувань"), locked while Blocked; a Member's none. No Metrics tile, no lists (user, 2026-10-20: "метрики забери, конекшени забери"). Last: Delete workspace (Owner) or Leave workspace (Member). |
| 8 | **Members is one list** with search, All · Members · Invited (only while something is pending) and statuses: invitations first, then the Owner, then members by name. An invitation row: the email + "Expires in N days" under it, the Status column the badge alone (Invited — while Blocked too; user, 2026-10-20). Role is plain text. No people count. The Owner has no actions; a member: Remove from Workspace; an invitation: Resend (locked while Blocked) · Revoke. |
| 9 | **Search where a list is long by nature** — Metrics, Members (and the Workspaces list); not on Connections (as My Connections, user 2026-10-19) nor on Files (as the Files page, user 2026-10-23: "з файлів пошук забери"). Metrics also has All · Built-in · Custom, Provider and Active only (Owner); Files All · Artifacts · Uploaded, Select all and bulk actions (Owner: Share via Workspace · Download · Remove from Workspace · Delete; Member: Add to Chat · Download). |
| 10 | **Adding a connection** shows where else it is shared, no re-auth; when the picks carry metrics, one line under the list says they go with them — no second step (user, 2026-10-20). No per-metric ticks. |
| 11 | **Where what is shared shows — one way, Owner** (user, 2026-10-20: Tag removed, "від таб відмовились"): in the person's own list, a people glyph after a shared item's name (its tooltip: "Shared by Olena Petrenko" / "In Marketing · Brand") and one Owner filter, on Data Sources, Metrics, Files and the Workspaces list. No Workspaces or Owner column — where an item is shared lives in its details panel (user, 2026-10-20). One item shared from several workspaces is one row. Every workspace name mentioned links to its page. Rows keep one height. With anything shared the list is never the empty state. A shared item opens its details panel read-only. |
| 12 | **One family of "unavailable"**, every one fixed by a plan: unavailable on your plan (Member's Free — rows listed, the page's "Shared … need Starter" notice), workspace unavailable (Blocked — a warning after the name, its popover saying why + Ask Owner to Renew, an email to the Owner; both at once → also "you'll need Starter"), one's own on Free (Upgrade to Pro), Create Workspace without the module (locked → Pro). Rows are not greyed; nothing reads as deleted. |
| 13 | **Blocked, Owner**: the notice with Upgrade to Pro in its sentence; Invite / Add / Resend shown locked (the one exception to "absent"); Remove from Workspace, Revoke, Delete still work. Back to active is said nowhere — no "available again" (user, 2026-10-23: "не потрібен"). |
| 14 | **The trial heads-up** (Plan Trial) says what stops — members lose access to one's own workspaces, what's shared needs a paid plan, nothing deleted — short, no names or counts (user, 2026-10-22: "задовгий текст"), dismissible, with See plans. |
| 15 | **Chat**: own + shared connections in one list (shared ones with their workspaces under the name); unavailable-on-plan and Blocked ones are not offered. No invitation banner anywhere (user, 2026-10-20: "банер запрошення ніде не треба") — the invitation is the email (rule 18). |
| 16 | **Disconnect** of a shared connection warns "Shared in Sales and Support" (no member count) and that it must be added again after reconnecting; it leaves those workspaces. **Create metric** warns while typing when the alias is shared already (theirs wins @revenue, the shared one stays @revenue__a3f9c1). **Delete Account** lists the workspaces deleted with it. |
| 17 | **Long names** — no switch: the sample mixes long names with typical ones (user, 2026-10-19). One-line places truncate with the full text in a tooltip; dialog titles, notices, toasts and the emails wrap. A workspace name stops at 50 characters (user, 2026-10-19). |
| 18 | **Emails** (`approved/workspace-emails.html`): the invitation (who, which workspace, sign in or create an account with this email, the expiry) and the renewal request a Member sends the Owner (why members lost access, nothing deleted, Upgrade Plan). |
| 19 | **Adding from where the item lives**: a connection's ⋮ and Connection details on Data Sources, a file's ⋮ and File details on Files — Share via Workspace (locked on Free), the same picker: every workspace of the person's, the ones it is in ticked and disabled ("Already in it"), a Blocked one disabled; + Create Workspace in place (name and description), back ticked; a connection's metrics said under the title. It only adds — taking out is a workspace's ⋮ or the panel's × (rule 21). |
| 20 | **Who shared it**: the glyph's tooltip names them everywhere; on the chat the review switch Owner (Hidden · Shown) adds "Olena Petrenko · Marketing" to the shared row. |
| 21 | **One details panel per item, identical wherever it opens** (user, 2026-10-22: "всі панелі не залежно від місця мали виглядати однаково!", "лишаєм нову панель всюди"): Connection details, Metric details, File details — on Data Sources, Metrics, Files, the Workspaces list and a workspace's page; only the handlers adapt. Its Workspaces section lists where the item is; × takes it out, after the same confirm as the ⋮ Remove from Workspace. |
| 22 | **One action, one wording** — the same confirm and toast wherever an action is done (user, 2026-10-22: "консистентність … тости"): added, removed, disconnected, deleted, metric created, checked, invited. |
